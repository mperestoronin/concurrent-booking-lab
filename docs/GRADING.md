# Оценивание: 100 баллов

Два эксперта проверяют один и тот же commit независимо, затем сопоставляют протоколы. Основание оценки: сохранённый вывод команд, фактическое состояние хранилищ, отчёт и объяснение автора. Монтаж видео и скорость речи не оцениваются.

## Функциональность: 60

Вес каждого B01–B10 указан в [TEST_CASES](TEST_CASES.md) и tests/cases.json. Сумма: 4 + 10 + 6 + 6 + 4 + 10 + 8 + 6 + 4 + 2 = **60**. Группа приносит весь вес только при прохождении всех утверждений. Ошибка setup, пропуск, падение teardown или отсутствие теста дают 0. Smoke не приносит баллов; при его падении сначала проверьте запуск, миграции и общий API-контракт. Изменённые исходные тесты проверяющий заменяет эталонными из учебного starter.

Прохождение теста даёт свидетельство для проверенного порядка операций. Эксперт также читает ограничение SQL и реализацию Redis: частный успех на тестовых именах, локальный mutex вместо защиты БД и отключение теста не удовлетворяют требованию. Если найден обход, баллы снимаются только за затронутые сценарии с указанием причины.

## Обязательное видео: 25

| Содержание | Баллы |
|---|---:|
| Воспроизведена исходная ошибка, объяснён порядок операций | 5 |
| Показаны исправленный захват и строка брони в PostgreSQL | 5 |
| Показаны неверный токен и истечение TTL | 4 |
| Объяснены атомарность Redis, SQL-ограничение и граница между ними | 7 |
| Показаны команды, результаты и commit проверенной версии | 4 |
| Итого | 25 |

Каждый пункт оценивается в полном диапазоне 0–вес: 0, если содержание отсутствует или неверно; половина веса с округлением вниз, если показана часть без объяснения; полный вес, если показаны результат и верное объяснение. Рекомендуемая длительность 3–6 минут. Видео обязательно: без доступной записи сдача не завершена и уровень не присваивается.

## Письменный отчёт: 10

| Содержание | Баллы |
|---|---:|
| Результаты до/после, команды, версия и непройденные тесты | 3 |
| Обоснование защиты Redis, уникальности SQL и авторизации | 4 |
| Границы TTL, известные ограничения и фактическое время | 3 |
| Итого | 10 |

Используется то же правило 0 / половина / полный вес. Пустой шаблон отчёта не получает баллов. Недоступные результаты нужно воспроизвести на проверяемом commit.

## Качество кода и оформления: 5

| Критерий | Баллы |
|---|---:|
| Минимальные читаемые изменения без обхода контракта | 2 |
| Миграция работает на существующей БД, команды воспроизводимы | 2 |
| Содержательный собственный тест и ясные пояснения нетривиального решения | 1 |
| Итого | 5 |

Для двухбалльных критериев: 0 при отсутствии, 1 при частичном выполнении, 2 при полном. Однобалльный критерий требует и теста, и пояснения.

Собственный тест размещается в tests/student и запускается отдельно; команда есть в [задании](ASSIGNMENT.md). Его отсутствие влияет только на этот 1 балл, не меняет функциональные 60 баллов и само по себе не препятствует уровню П/Э.

## Уровни

| Уровень | Условие |
|---|---|
| Пока не зачтено | Меньше 60 баллов либо недоступное обязательное видео/пустой отчёт |
| Б | 60–74, доступное видео и заполненный отчёт, основной сценарий B01 работает |
| Б+ | 75–89 с теми же условиями; также верхняя граница при 90+ без полного base или 20/25 за видео |
| П | 90–100, base 60/60, видео не меньше 20/25, отчёт заполнен |
| Э | Все условия П, E01 и E02 проходят, оба дополнения объяснены технически верно |

Дополнения не прибавляют баллов сверх 100. Для Э эксперт вручную подтверждает анализ E02: порядок событий, отсутствие общей атомарности, сохранённый SQL-инвариант, предложенное усиление и его цена. Зелёного E02 без объяснения недостаточно. Если основной сценарий B01 не работает, работа возвращается на исправление независимо от суммы частных баллов.
