# Сдача и проверка

Работайте в собственном Fork. Исходный репозиторий содержит starter, решения в его main не переносятся.

1. Создайте Fork после публикации учебного репозитория и клонируйте его. Создайте ветку, например solution. Сохраните commit исходного starter, чтобы показать ошибку до исправления.
2. Исправьте сервис и добавьте миграцию. Сохраните результаты исходного base отдельно; затем выполните итоговые smoke, base и, для Э, expert.
3. Заполните [REPORT](../REPORT.md). Укажите commit, реальные результаты, время и ограничения. Результаты в reports исключены из Git, поэтому приложите JSON/Markdown к сдаче, к PR или по доступной ссылке. Не публикуйте пароли, .env, volumes и .instructor.
4. Запишите видео 3–6 минут, проверьте звук и доступ по ссылке без запроса разрешения. Ссылку добавьте в REPORT.
5. Отправьте ссылку на свой репозиторий и commit либо откройте PR из своего Fork в исходный репозиторий для проверки. Применяйте PR только если это согласованный преподавателем способ сдачи. Такой PR эксперты закрывают без merge. Альтернатива: PR внутри собственного Fork и ссылка на него.

## Сценарий видео

| Время | Показать и объяснить |
|---|---|
| 0:00–0:45 | Что бронируется, версия starter, исходный красный сценарий с двумя победителями |
| 0:45–1:45 | Исправленный захват и подтверждение, состояние Redis и PostgreSQL |
| 1:45–2:45 | Истёкший/неверный holdId, один действительный владелец |
| 2:45–4:15 | Код ключевых изменений, SQL-ограничение, авторизация и commit |
| 4:15–5:15 | Итоговый base, известная гонка TTL, при выполнении дополнений их результат |

Допустимо сократить паузы запуска. Не нужно показывать установку Docker или записывать часы разработки. Для исходной версии используйте сохранённый результат и отдельную демонстрацию B02; не подменяйте её вымышленным выводом. Временный checkout старого commit делайте в отдельной копии, чтобы не потерять решение.

## Комплект сдачи

- Ссылка на репозиторий/PR и точный commit.
- REPORT с реальными результатами, анализом, временем и ссылкой на видео.
- JSON и Markdown итогового base; исходный base для сравнения.
- Для Э: expert-результаты и раздел об обоих дополнениях.

Перед сдачей воспроизведите запуск из чистого клона в отдельном Compose-проекте. Для изоляции задайте другой API_PORT в .env и используйте docker compose -p booking-review ... во всех командах этой копии. Volume будет отдельным; занятый порт одного экземпляра не должен мешать другому.

Эксперты независимо запускают тесты и читают решение на одном commit. При расхождении они прикладывают результаты, указывают версию окружения и согласуют баллы по [GRADING](GRADING.md). Изменённые или отключённые исходные тесты не служат основанием для баллов.
