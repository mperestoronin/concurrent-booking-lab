# Проверка подготовленного starter

Дата: 19 октября 2026 года, Europe/Moscow. Это протокол подготовки лабораторной, не студенческий отчёт и не оценка учебного решения.

## Среда

macOS arm64, локальная Colima, Docker Engine 29.5.3, Compose 5.1.4 в виде отдельного docker-compose. Стенд использует Python 3.12.13, PostgreSQL 16.13 и Redis 7.4.8. В этом окружении стандартный плагин docker compose отсутствовал, поэтому фактически запускался совместимый standalone docker-compose с теми же аргументами.

## Источники структуры и содержания

Изучены реальные README обоих указанных примеров: [DevSecOps Python Lab](https://github.com/iirraaaaaaaaaaaa/devsecops-python-lab) и [n8n topic](https://github.com/CehhGhost/low_code_n8n_topic). Дополнительно прочитаны постановка DevSecOps, структура n8n, его Compose, раннер и критерии оценивания. Самостоятельно использованы разделение базовой/дополнительной работы, готовое окружение и проверка через отчёт/видео. Код и тексты примеров не переносились.

Технические источники приведены рядом с утверждениями в THEORY и TOPIC_NOTE; ссылки проверялись по официальной документации PostgreSQL, Redis и psycopg.

## Границы проверки

GitHub Actions подготовлен, но удалённо не запускался. Windows и Linux отдельно не проверялись. Время студента 8,5 + 2,5 часа пока оценено по этапам; пробное прохождение другим студентом не проводилось. Поведение при аварии хоста, сетевом разделении и failover Redis не входит в проверенную модель.

Перед публикацией эксперт повторяет запуск на втором компьютере, назначает двух проверяющих, проверяет канал сдачи и пробным прохождением уточняет трудоёмкость. Полный список действий: [INSTRUCTOR_GUIDE](INSTRUCTOR_GUIDE.md).

## Финальное ревью

Сопоставлены задание, API-контракт, OpenAPI, код сервиса, тесты, шкала и план времени. Исправлены следующие расхождения:

| Находка | Исправление |
|---|---|
| OpenAPI показывал стандартный detail вместо фактического error | Добавлены модели ошибок и ответы 409/422/500/503 в схему; S05 сверяет их |
| Обработчик 405 терял заголовок Allow | Заголовки HTTPException сохраняются, S04 проверяет результат |
| Ошибка команды Redis считалась недоступностью хранилища | Ошибки соединения/таймаута дают 503, ошибки команды дают 500; S01 проверяет различие |
| Проверки могли пропустить слишком широкий перехват SQL-ошибок | B08 проверяет настоящий конфликт ресурса и отдельное нарушение первичного ключа |
| Тестовая БД создавалась с нуля и не проверяла обновление старой схемы | Добавлен снимок исходной схемы с контрольной бронью; миграция должна сохранить её поля |
| Неполное покрытие смены токена и освобождения | Добавлены повторная аренда тем же клиентом, неизменность данных при отказе и сохранность подтверждённой брони после удаления ключа |
| Режим раннера зависел от названий функций | Выбор base/expert основан на manifest |
| Собственный тест одновременно выглядел обязательным и оценивался отдельно | Это отдельный критерий качества на 1 балл, с каталогом и командой запуска |
| Время не выделяло резерв и объём семинарских материалов | 450 минут этапов + 60 минут резерва; дополнения 150 минут. Семинарские записка и слайды уже готовы |
| Избыточное выделение слов обратными кавычками | Удалено из Markdown вне блоков кода; команды в блоках сохранены |

Состав набора и шкала сохранены: 5 smoke, 10 базовых сценариев на 60 баллов и 2 дополнения. Эталон остаётся локальным, учебные дефекты starter не исправлялись. Время 8–9 часов для базы и 10,5–12 часов с дополнениями реалистично для указанной подготовки, но пока не подтверждено пробным прохождением. Установка Docker с нуля и изучение основ Python/SQL потребуют отдельного времени.
