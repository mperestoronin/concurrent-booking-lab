## Одно место, два успешных ответа

1. A проверяет: место свободно
2. B проверяет: место свободно

Инвариант: **не больше одной подтверждённой брони на ресурс**

## Гонка захвата Redis

```text
Время     A                    B
  1       GET → ключа нет
  2                            GET → ключа нет
  3       SET tokenA → OK
  4                            SET tokenB → OK
```

Два HTTP 201, но действителен лишь последний токен

Условие и запись нужно объединить: SET … NX PX …

## Окончательное решение PostgreSQL

- UNIQUE выражает инвариант ресурса
- Транзакция фиксирует подтверждение
- Конкурирующий INSERT получает конфликт
- API возвращает 409, а не вторую бронь

Предварительный SELECT может устареть

## TTL: авторизация и commit

```text
A: действительный токен → авторизация → пауза
Redis:                     TTL истёк
B:                         новый токен → COMMIT
A:                                      INSERT → 409
```

После авторизации TTL может истечь

**Общей транзакции Redis/PostgreSQL нет**

<!-- 3:45–4:45. Точный контракт: истечение до авторизации запрещает подтверждение; после неё SQL-попытка допустима. В E02 первым фиксируется B. При другом порядке может победить ранее авторизованный A. Двух SQL-броней не должно быть в обоих случаях. -->
